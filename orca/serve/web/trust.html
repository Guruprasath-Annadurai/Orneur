Trust & Security

Our real, current posture — including what isn't done yet. Nothing here is aspirational; every claim maps to something specifically enforced in the running product today.

Compliance & data handling
●SOC 2

In progress — not yet certified. On our roadmap as we grow; no target date is committed yet.

✓ Data retention

Customizable retention windows; no permanent storage of prompt data by default.

✓ PII handling

Flagged, not silently altered. Real-time scanning identifies PII in model output without rewriting it — it's usually your own data, and silent alteration would be worse than disclosure.

✓ Secrets & credentials

Automatically redacted from responses before they reach you — API keys, tokens, and private-key blocks are actively stripped, not just flagged.

✓ Model training data

Production conversation data is not used to train Orca's models without separate, explicit opt-in.

✓ Two-factor authentication

TOTP-based 2FA available on every account, enforced at login when enabled.

Application security
✓ Sandboxed code execution

Code-interpreter and shell tools run through an AST-based denylist and a command allowlist — dangerous imports, built-ins, and interpreters are blocked before execution, not after.

✓ Sandboxed file access

File read/write tools are restricted to a dedicated workspace directory — path traversal and absolute-path escapes are rejected.

✓ SSRF protection

Outbound web-fetch tools resolve and reject private, loopback, and link-local addresses before making a request, and fail closed if resolution fails.

✓ Dependency security

Automated vulnerability scanning (pip-audit) runs on every push and pull request, gated in CI — not a manual, occasional check.

✓ Rate limiting

Sensitive endpoints (password reset, login, signup) are rate-limited per IP — e.g. password-reset requests are capped at 3/hour/IP to slow credential-stuffing and enumeration attempts.

✓ Audit logging

Security-relevant events — output redaction findings, account changes, admin actions — are written to an append-only audit log.

This list only includes controls that are actually implemented and tested today. Full methodology for how we measure model accuracy and safety scores: how we measure these numbers.

Found a problem?

If you've found a security vulnerability in Orca, we want to hear about it before anyone else does.

Email hello@atheris.ai with a description and reproduction steps. We don't yet run a paid bug-bounty program or a dedicated security mailbox — we will credit and acknowledge good-faith reports, and we ask that you give us reasonable time to fix an issue before public disclosure.
