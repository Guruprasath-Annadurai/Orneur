# ORNEUR Identity Audit

Repository-wide, evidence-based inventory of Orca/Atheris identifiers as of
this closure (branch `session-update-2026-08-25`, prior HEAD
`99e743b68b94c056a5f6b17016cefffe62bbd0c7`). This is not a blind
find-and-replace list — every row was classified before any change was
made, per this closure's own instructions. Rows marked **FIXED** were
corrected during this closure; rows marked **DEFERRED**/**LEGACY** were
deliberately left as-is, with a reason.

This audit builds directly on the prior, planning-only
`docs/orneur/phase-0/BRAND_MIGRATION_PLAN.md`, which already inventoried
the mechanical scope of a full `orca` → `orneur` package rename (112 files,
42 `ORCA_*` env vars, Ollama model names, Kaggle slugs). That plan is not
duplicated here; this audit covers the narrower, immediately-actionable
public-identity surface this closure addresses.

## External verification performed (read-only, no publication)

| Check | Method | Result |
|---|---|---|
| Is `orca-ai` published on PyPI? | `GET pypi.org/pypi/orca-ai/json` | **YES** — versions 0.1.0/0.1.1, published by **"Orca Systems"** (`github.com/orca-systems/orca`), an **unrelated third party**. This project's own version (1.0.0, later renamed to `orneur`) has never matched or been published under that name. |
| Is `orneur` published on PyPI? | `GET pypi.org/pypi/orneur/json` | 404 — unregistered, available. |
| Does `orca.systems` serve this project's installer? | `HEAD https://orca.systems/install.sh` | **404 Not Found.** |
| Is `orca.systems` reachable at all? | `HEAD https://orca.systems` | 403 Forbidden — the domain exists and responds, but is not this project's infrastructure (consistent with belonging to the same "Orca Systems" third party above). |
| Is `atheris.ai` reachable? | `HEAD https://atheris.ai` | Timed out — no evidence this domain is live or controlled by this project. |

**Consequence discovered mid-closure (real defect, not cosmetic):**
`orca/upgrade.py`'s self-update mechanism checked
`https://pypi.org/pypi/orca-ai/json` for "the latest version" — i.e. a
stranger's unrelated package. It was silently harmless only because the
local version (1.0.0) happened to exceed that package's (0.1.1); had the
unrelated project ever published a higher version number, `orneur upgrade`
would have silently `pip install --upgrade orca-ai`'d a stranger's software
over the user's real installation. **Fixed** — see `_PACKAGE`/`_PYPI_URL`
in `orca/upgrade.py`, now pointing at `orneur` (unregistered, so
self-update honestly reports "could not reach PyPI" until this project
actually publishes).
