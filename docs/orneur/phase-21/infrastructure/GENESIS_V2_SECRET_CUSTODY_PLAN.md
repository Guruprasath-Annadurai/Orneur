## Absolute rules (restated from the task's own non-negotiables)

- **No secret value is ever placed in a GitHub repository file.** Registries (`AUTHORITY_REGISTRY.json`, `CORPUS_GENERATOR_REGISTRY.json`, etc.) hold only **public** material (public keys, identity metadata, status) — this is already how the existing code is structured, and this plan does not change it.
- **No secret value is ever printed into a terminal log.** Every preflight/evidence tool in the existing codebase (`store.py`'s `*_setup_preflight`, `scripts/genesis_v2_evidence_snapshot.py`) already reports presence/shape booleans only, never values — real deployment tooling built on top of this plan must preserve that discipline.
- **No secret value is ever exposed in chat, in an issue, in a PR description, or in any AI-assistant conversation** — including this one. This document names *what* secrets exist and *where* they will live; it contains zero actual secret material because none has been created.

## What this phase does NOT do

Generate any of the above. Every row's "where stored" is a design target, not a current state. The single next safe action (see the final report, §L) is strictly limited to code-level and documentation work — not secret creation.
