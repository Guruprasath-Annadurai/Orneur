# Genesis V2 — Tier0-S final remediation (re-audit findings N1–N10)

Base: `5debb7524f910545f814d122fdd7ba0217ff9913`. Re-audit verdict that triggered this phase: `TIER0_S_FINAL_REAUDIT_FAIL` (no CRITICAL or HIGH finding; three confirmed MEDIUM fail-open paths and several LOW/INFORMATIONAL weaknesses). Doctrine applied: a known fail-open security control blocks advancement; no gate was weakened; every discovered weakness was attacked again after the fix by independent scripts, not only by the shipped regression tests.

This document records what changed. It does **not** declare Tier0-S fully accepted, provisionable or ready for real secrets. The maximum conclusion of this phase is `READY_FOR_FINAL_INDEPENDENT_REAUDIT`. It makes no Decision 9, authorizes nothing, and leaves `CORPUS_GENERATION_AUTHORIZATION = NOT_AUTHORIZED`, `private_storage_genuinely_configured = false` and all seven authorization flags `false`. The interlock log still earns **no assurance credit**; cold boot and physical detachment remain owner procedures.

## Additional weaknesses found while attacking adjacent logic (fixed in this phase)
| Finding | Severity | Fix |
|---|---|---|
| A route-table column header with a row joined onto it (a deleted newline) matched as "header" and swallowed the default route | MEDIUM (fail-open, found by the single-character sweep) | Header must equal the exact column list |
| A harmless `ifconfig` line (`ether`, `media`, …) accepted arbitrary trailing text, so a joined `inet` or interface header was swallowed | MEDIUM (fail-open, found by a status-less single-character sweep) | No TAB or `: flags=` inside a harmless line; interface names are additionally cross-checked against `ifconfig -l` |
| `$` in the UUID / SHA-256 / environment-id patterns also matched before a trailing newline | LOW | Patterns end in `\Z` |
| A file modified in place between the directory listing and its open was accepted if the inode matched | LOW | Size and mtime of the opened descriptor must equal the listing |
| The interlock verifier and writer resolved files through a pathname after the directory check | LOW | Verification and append go through the one locked, `O_NOFOLLOW`-opened directory descriptor |
| `main` could end in a traceback on an unexpected exception | LOW | Any unexpected exception prints `FAIL_CLOSED internal error` and `GATE_FAILS` |

## What stays exactly as it was
The Tier0-S design, the cold-boot/detachment owner procedures, the advisory-only interlock, the keyless-versus-keyed transfer claim levels, the unchanged AES-256-GCM verification in `store.py`, the protected benchmark and corpus inventory files, and every authorization flag. The daily-driver stays rejected: a read-only diagnostic against it still returns `GATE_FAILS`.

## Remaining residual limitations
Not continuous; bypassable by a malicious owner/root or by anyone who can alter the machine, the gate, its inputs or both the manifest and its pin; known-name and known-location lists are not exhaustive; only the invoking user's home is inspected; the owner-key scan is weak name/first-bytes evidence; the socket table is a point-in-time snapshot and UDP absence is not claimed; removal of a whole well-formed telemetry row and truncation inside the last `ifconfig` block are undetectable; label matching is spoofable and a well-formed wrong UUID is inert; the ancestors of a walked root are resolved normally; hashing is point-in-time; inode comparison is best-effort on filesystems that reuse inodes; physical detachment and cold boot have no software proof; the OS returns a reduced telemetry view (for example no Internet socket section) to processes whose lineage includes a non-Apple executable; this was first described here as a property of "some Python builds", which was wrong, and is characterized and handled in `GENESIS_V2_TIER0S_W1_W2_REMEDIATION.md`.

Status of this phase: `READY_FOR_FINAL_INDEPENDENT_REAUDIT` — not accepted, not provisioned, not authorized.
