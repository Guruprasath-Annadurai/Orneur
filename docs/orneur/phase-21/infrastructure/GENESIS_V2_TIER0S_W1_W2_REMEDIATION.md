# Genesis V2 — Tier0-S acceptance-blocking remediation (W1, W2) and related findings (W3, W5, W6)

Base: `e93a692b683e0eac7a61dfb4c7600024495365c3`. Acceptance re-audit verdict that triggered this phase: `TIER0_S_SOFTWARE_GATE_REJECTED` (W1: MEDIUM, telemetry completeness; W2: MEDIUM, documentation overclaim). This document records what changed and what was measured. It does **not** declare the software gate accepted, Tier0-S provisioned, or anything authorized. The maximum conclusion of this phase is `READY_FOR_ACCEPTANCE_REAUDIT`. `CORPUS_GENERATION_AUTHORIZATION` stays `NOT_AUTHORIZED`; all seven authorization flags and `private_storage_genuinely_configured` stay `false`; the interlock log still earns no assurance credit; cold boot and physical detachment remain owner procedures.

Governing rule for this phase: **exit status 0 plus syntactically valid output is not complete telemetry.** The state `STRUCTURALLY_VALID_BUT_COMPLETENESS_UNPROVEN` must never become PASS; it becomes `FAIL_CLOSED` with the sanitized reason `TELEMETRY_COMPLETENESS_UNPROVEN`.

## D. W1 root cause (measured on macOS 27.0.1 / 26A434, this host)
macOS returns a **reduced telemetry view** to the trusted system tools, with exit status 0, depending on the **process lineage** of the caller.

| Lineage of the process that runs the tool | Internet socket section | Neighbour (host) routes | Hardware addresses | Interface names / addresses (libc) |
|---|---|---|---|---|
| Apple-signed ancestors only (`zsh`, `ruby`, `perl`, `/usr/bin/python3`, and their children) | present | present | real | complete |
| Any non-Apple ancestor (Homebrew `node`, `uv`, the uv-managed Python used by the project `.venv`) — **including Apple-signed children** such as `/bin/sh`, `env -i`, `/usr/bin/python3` started from it | **absent** | **absent** (5 IPv4, ~60 IPv6 on this host; the `default` rows survive) | all redacted to `02:00:00:00:00:00` (12 of 12; 0 of 12 in the full view) | **identical** |

Findings that shaped the design: (1) the property follows **ancestry**, not the immediately launched binary; (2) which ancestor property triggers it is **not identified** (copying the interpreter breaks its relative layout and the system re-applies the provenance attribute, so the experiment was inconclusive) — only the empirical split above is claimed; (3) the **raw kernel route dump** (`sysctl` `NET_RT_DUMP`) returns the reduced set too (66 vs 152 records), so it is **filtered identically** to `netstat -rn` and is **NOT independent** of it; (4) the kernel PCB counters, the kernel PCB **list** itself (`net.inet.tcp.pcblist64`: 87 records in both lineages while `netstat` printed 0 TCP rows in the reduced one) and libc `getifaddrs()` / `if_nameindex()` are **unaffected**, so for sockets the reduction happens in the `netstat` path, whereas for routes it happens in the kernel dump itself (the filter's location differs by table; no mechanism is claimed beyond these measurements); (5) the UDP counter equals the kernel `pcblist` record count, but `netstat` omits some UDP PCBs by design and the omitted number is unstable (rows/counter 0.77, then 36 rows against 102 PCBs during a burst), so **no trustworthy UDP relationship exists**; (6) agent/IDE terminals do **not** by themselves induce it (the harness shell is unfiltered); launching a non-Apple interpreter from them does. A dedicated Tier0-S environment is likely to be unfiltered only if the gate is started from Apple-signed tooling; the gate does not guess, it tests the symptoms.

## I. Telemetry-source independence
| Source | Security fact | Mechanism | Independent from | Known filtering |
|---|---|---|---|---|
| `ifconfig -a` | interface addresses, UP/RUNNING flags, `status: active`, hardware addresses | `ifconfig` tool (getifaddrs + per-interface ioctls) | — | hardware addresses redacted in the reduced view; addresses and names intact |
| `ifconfig -l` | interface names | same tool | **not independent** of `ifconfig -a` (same tool); kept only as a truncation cross-check | none observed |
| libc `getifaddrs()` | interface names, flags, IPv4/IPv6 addresses | in-process libc call (ctypes, no library path searched) | the `ifconfig` tool and its ioctls; **partially** independent (same kernel interface list) | none observed |
| libc `if_nameindex()` | interface names | in-process libc call | `ifconfig`; shares the kernel list with `getifaddrs` | none observed |
| `netstat -an` | TCP / UDP / ICMP socket rows | `netstat` reading the kernel PCB lists | — | **whole Internet section absent in the reduced view** |
| `sysctl net.inet.tcp.pcbcount`, `net.inet.raw.pcbcount` | number of TCP / raw PCBs | kernel counters, read by the fixed `sysctl` tool, before **and** after the socket query | the `netstat` row listing | none observed |
| `sysctl net.inet.tcp.pcblist64` (kernel PCB list) | every TCP socket with its addresses | binary kernel records | `netstat`; **unfiltered** in the reduced lineage (87 of 87 records). **Not used**: the record layout is private and version-dependent, so parsing it would be brittle — a recorded option for a future, stronger socket source | none observed |
| `sysctl net.inet.udp.pcbcount` | number of UDP PCBs | kernel counter | — | **not used**: no stable relationship to `netstat` rows exists |
| `netstat -rn -f inet|inet6` | default / interface routes | `netstat` reading the kernel route table | — | neighbour routes removed in the reduced view |
| raw `sysctl` `NET_RT_DUMP` | the same routes | kernel route dump | **NOT independent** of `netstat -rn`: filtered identically | same as `netstat -rn` |
| `ether 02:00:00:00:00:00` | the reduced-view signature | value present in the reduced `ifconfig` | indicator derived from the filtered source itself; **an indicator, not proof** | — |

`netstat -an` and `netstat -rn` share the filtering layer, so agreement between them is **not** evidence. Independent evidence exists for interface facts (libc) and for TCP / raw socket counts (kernel counters). **No independent route-completeness source exists**, so the route table's completeness is never claimed.

## E–G. Design
**Sockets.** Parsed TCP (`tcp*`) and raw/ICMP (`icm*`) rows are compared with the kernel counters read before and after the socket query. Per class: `rows >= max(1, floor(0.75 × lower counter))` and `rows <= 2 × higher counter + 16`. This detects removal of the Internet section or of most TCP/raw rows; it deliberately does **not** detect removal of a few rows, and it says nothing about UDP (observation-only, UDP completeness unproven, UDP absence not claimed). Any counter that is missing, unreadable, non-integer, negative, boolean, above 10^7, or has the wrong shape is `FAIL_CLOSED`.

**Interfaces.** `ifconfig -a` must agree with libc `getifaddrs()` and `if_nameindex()` on the name set, the UP / LOOPBACK flags and the IPv4/IPv6 address sets (KAME-embedded link-local scope normalized). Any disagreement, missing inventory, duplicate name or missing loopback is `FAIL_CLOSED`.

**Routes / network question.** The security question is *is usable non-loopback networking present?* It is answered from the interface addresses and status (independently cross-checked). The route table can only **add** a failure, and it must contain a route row for every UP, addressed, non-loopback interface of the independent inventory (otherwise completeness is unproven). A PASS of `network_no_default_route` says "none observed" and states that completeness is not claimed.

**Reduced-view detection.** The `02:00:00:00:00:00` hardware address, or a socket-counter inconsistency, marks `ifconfig`, `routes4`, `routes6` and `sockets` all `TELEMETRY_COMPLETENESS_UNPROVEN`, because they share the filter. A violation still visible in a reduced view remains `FAIL`. Whether `02:00:00:00:00:00` can occur legitimately is not established by a primary source (a public search found no authoritative statement); a host that really assigns it fails closed, which is safe.

## Preserved controls
Trusted-home resolution, fixed absolute tool paths, the strict parser grammar, volume configuration validation, manifest/hash checks, descriptor-relative traversal, transfer special-file rejection, interlock locking, AES-GCM verification, daily-driver rejection and fail-closed handling are unchanged. Their existing tests pass unmodified apart from fixtures that now supply the new mandatory sources.

## Remaining residual limitations
Not continuous; bypassable by a malicious owner/root or anyone who can alter the machine, the gate, its inputs, or both the manifest and its pin; known-name and known-location lists are not exhaustive; completeness is a bounded plausibility comparison, not a proof that every row is present; UDP completeness is unproven; the route table's completeness is not claimed; the ancestor property that triggers the reduced view is not identified; label matching is advisory; physical detachment and cold boot have no software proof.

Status of this phase: `READY_FOR_ACCEPTANCE_REAUDIT` — not accepted, not provisioned, not authorized.
