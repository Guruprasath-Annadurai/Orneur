## Summary of what Phase A found

- **No breaking changes to already-integrated surfaces** (auth, base streaming, history, search, B15 citations). The new backend is additive there.
- **Two newly-confirmed, source-verified correctness gaps in the already-shipped B16 work**, not previously known:
  1. `DELETE /api/docs/{doc_id}` can return **HTTP 200 with `{"deleted": false}`** — my current `removeAttachment()` only checks `r.ok`, which would treat this as success. This is a stronger version of the "404 doesn't prove deletion" concern the CTO addendum raised — it turns out even a 200 doesn't always prove it.
  2. Both upload and delete can now return **403 `retrieval_unauthorized`**, not handled distinctly today.
- **B11 and B13's entire "honest disabled-state" premise is now obsolete** — real backends exist for both. Their current implementations are not wrong (they were honest about a real absence at the time), but they are now stale and must be reconnected, not redesigned.
- **B14's correlated runs are additive and narrow** — existing Quick Switch needs no changes; a run is explicitly not a workspace/access grant.
- **B06/B09 is wholly new surface** with an explicit, narrow sharing model (no contact picker, no public links).
- **C-series: no change.** Directive confirmed, not contradicted.
