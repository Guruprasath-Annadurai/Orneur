# GPU allocation and failure-mode specification (Workstream G)

Status: **DESIGN. No GPU was allocated, requested, probed or used to write this document.** `TRAINING_AUTHORIZATION.json` is `NOT_AUTHORIZED`, `gpu_allowed` is false, and nothing in this change can flip that.
Each row below is labelled **IMPLEMENTED_TESTED_SYNTHETIC** (the control exists in `orca/train/dryrun/` and is proven by a test against the pure-Python toy run, which has no GPU), **PARTIAL** (the generic control exists, the GPU-specific detector does not), or **DESIGN** (specification only; cannot be tested without a GPU and a grant).
"Tested on the toy" proves the *control flow* (stop, roll back, record, resume). It does not prove that a real CUDA failure raises the exception this document says to catch.

## 1. Allocation model (DESIGN)

A GPU may be allocated only inside a run whose authorization the existing gate has verified. Nothing in this section relaxes `orca/train/authorization.py`.

| Rule | Specification | Existing control it builds on |
|---|---|---|
| No grant, no allocation | The allocator is called only with a verified `TrainingGrant` (`require_grant` + `verify_integrity`). The allocator never accepts a "dry run", "force" or environment switch. | `authorize_training`, `require_grant`; `tests/test_trainprep_authorization.py::test_no_entry_point_has_a_bypass_parameter` |
| GPU permission is explicit | `permissions.gpu_allowed` in the signed record and `gpu_permission` on the authority key must both be true. | `verify()` -> `GPU_NOT_AUTHORIZED`, `AUTHORITY_LACKS_GPU_PERMISSION` |
| Allocation record, written BEFORE the request leaves the host | `{authorization_id, run_slot, provider, region, gpu_type, gpu_count, interruptible, max_hourly_usd, max_hours, requested_at}` appended to the run ledger as a new event type (`gpu_allocation_requested`). If the append fails, nothing is requested. | `RunLedger` (chained, anchored) |
| Allocation never exceeds the grant | `gpu_count * max_hourly_usd * max_hours <= record.limits.max_spend_usd`, and `max_hours*60 <= max_wall_clock_minutes`. Checked before the provider call. | `ResourceBudget` caps; `requested_spend_usd` binding in `authorize_training` |
| Environment class is fixed | `SELF_HOSTED_GPU` or `SSH_RENTED_GPU` as signed. A different provider, region or instance class than recorded is a new authorization, never an automatic failover. | `WRONG_ENVIRONMENT_CLASS` |
| Teardown is part of the run | Release is attempted on every exit path (finish, stop, abort, crash handler). A release failure is an incident (section 3), recorded, and blocks any further allocation under that authorization. | design |
| Orphan detection | A reconciler lists instances tagged with the `authorization_id` and compares with the ledger; any instance with no live run is terminated and recorded. | design |
| Remote kill propagation | The local kill switch (file or flag) is mirrored to the remote host (touch a file on the instance and `SIGTERM` the process group). The remote loop checks it before every step. | `KillSwitch` is checked before every step and micro-batch (tested) |

Not implemented and not testable today: provider SDK calls, instance tagging, billing telemetry, any remote host action.

## 2. Failure modes

| # | Failure | Detection | Containment | Rollback | Evidence | Status |
|---|---|---|---|---|---|---|
| 1 | **CUDA out-of-memory** | Catch the framework OOM exception around the step; confirm with the driver's memory counter. | The step is atomic: it computes on a copy and commits only on success (`ToyEngine.compute_step` returns a clone). On OOM: abort the step, record, STOP. No automatic retry with a smaller batch or shorter sequence (that changes the run; `max_seq_length` and epochs are authorization-bound). | State returns to the last committed step; a rollback checkpoint of that step is saved so resume has a target. | Ledger `step_aborted{reason}` then `run_stopped`; sealed manifest `failure_state`. | Generic abort-and-rollback: **IMPLEMENTED_TESTED_SYNTHETIC** (`test_exception_mid_accumulation_rolls_back_to_the_last_committed_state`). OOM detector: **DESIGN**. |
| 2 | **Preemption / spot eviction** (SIGTERM, instance reclaimed) | Signal handler on `SIGTERM`/`SIGINT`; provider metadata "terminate" notice polled at most every N seconds. | Handler sets the kill flag; the loop stops at the next micro-batch check; no new step starts. A hard kill with no notice is covered by atomic checkpoints. | Resume from the newest checkpoint that verifies AND is recorded in the ledger. In-flight step is lost, never half-applied. | `step_aborted{INTERRUPTED:...}`, `run_stopped`, later `run_resumed{from_step, from_digest}`. | Interrupt rollback and resume: **IMPLEMENTED_TESTED_SYNTHETIC** (`test_keyboard_interrupt_is_recorded_rolled_back_and_re_raised`, resume byte-identity tests, crash-mid-checkpoint tests). Signal wiring and provider notice: **DESIGN**. Resumes are the same run: step/token/spend caps are cumulative (tested). The wall-clock cap is per process invocation (limit: documented, bounded in practice by the step cap and the grant expiry). |
| 3 | **NCCL / driver / Xid failure, hung collective** | Watchdog timeout on each step (no heartbeat from the loop for T seconds); collective timeout; driver Xid lines (`dmesg`/DCGM). | Kill the process group; do NOT retry on a different node under the same slot without operator action; mark the instance suspect. | Same as #2: last verified checkpoint. | Watchdog writes `run_stopped{reason: WATCHDOG}`; Xid excerpt stored with the run, referenced by hash. | **DESIGN** (no multi-GPU or driver exists to test). The wall-clock hard stop covers a hang only if the loop regains control; the watchdog must be an external process. |
| 4 | **Silent NaN / Inf loss or exploding gradients** | Every step: loss and every gradient finite BEFORE commit (`NonFiniteValue`); also parameters finite after the update. Spike rule (loss > k x moving median) is a policy to add. | The poisoned step is discarded; the run stops. No "skip the bad batch and continue" (it would change the data order the run is bound to). | Last committed state; resume reproduces the uninterrupted result exactly, because the poison was never committed. | `step_aborted{NON_FINITE_LOSS}`; no NaN ever appears in `losses` or a checkpoint (asserted). | NaN/Inf check: **IMPLEMENTED_TESTED_SYNTHETIC** (`test_nan_loss_is_detected_before_commit_and_rolls_back`). Mixed-precision overflow handling and spike thresholds: **DESIGN**. |
| 5 | **Checkpoint corruption** (bit rot, truncation, partial write, malicious edit, missing sidecar, forged sidecar) | Verify on every load: sidecar self-hash, directory identity via `hash_artifact_directory`, `CheckpointRecord.verify_integrity`, plan hash, digest cross-checked against the independent run ledger, "recorded in ledger" required. Loading unverified state is impossible by construction. | The bad checkpoint is moved to `quarantine/` (never deleted, never loadable); resume falls back to the newest good one. Writes are atomic (tmp, fsync, rename, then sidecar commit), so a crash cannot produce a loadable half-checkpoint. | Newest verified checkpoint; if none verifies the resume is REFUSED (`NO_VERIFIED_CHECKPOINT`). | `run_resumed{rejected_checkpoints}`; quarantined files kept as evidence. | **IMPLEMENTED_TESTED_SYNTHETIC** for the toy format (`tests/test_trainprep_checkpoint.py`, 30 tests). Real sharded safetensors/GGUF: reuse `validate_checkpoint_artifact` + `hash_artifact_directory` (existing registry code); the glue is **DESIGN**. |
| 6 | **Provider outage / API errors / quota** | Provider calls wrapped with a bounded retry (count and total time capped in the allocation record); health probe before allocation. | After the cap: STOP. No silent failover to another provider, region or instance class (authorization-bound). Already-incurred spend still counts. | Last verified checkpoint, resumed only on the same authorized environment. | `gpu_allocation_failed{provider, error_class}` in the ledger; no secrets or response bodies stored. | **DESIGN**. The hard-stop and cumulative-cap machinery it depends on is **IMPLEMENTED_TESTED_SYNTHETIC**. |
| 7 | **Cost overrun** (spend, tokens, steps, wall clock) | Before every step: steps, tokens, simulated spend (integer micro-USD, no float drift), wall clock, kill switch. Real spend would come from provider billing telemetry polled out-of-band. | The offending step is never started. Default caps are 0 = nothing runs. A cap of 0 on any dimension means "no allowance", never "unlimited". Caps are cumulative across resumes. | n/a (the run simply stops; a rollback checkpoint of the last committed step is saved). | `run_stopped{STEP_CAP|TOKEN_CAP|SPEND_CAP|WALL_CLOCK_CAP|KILL_SWITCH}`; usage in the result. | Control: **IMPLEMENTED_TESTED_SYNTHETIC** (`tests/test_trainprep_budget.py`, 33 tests; covers register P2-4 "spend above the cap is refused, cap may remain 0"). Real billing telemetry: **DESIGN**; until it exists the real spend cap is only the pre-run estimate checked by the gate. |
| 8 | **Audit-trail loss** (log truncated or rewritten to hide a run) | Chain verification plus head anchors; see `AUDIT_LOG_RETENTION_ARCHITECTURE.md`. | Writers refuse to extend a log that does not verify. | Restore from the external anchor's last known head. | Anchor files, chain heads. | Local: **IMPLEMENTED_TESTED_SYNTHETIC**. Off-host anchor: **DESIGN**. |

## 3. Incident handling (DESIGN)

Any of: failed release, orphan instance, anchor mismatch, unverifiable checkpoint with no fallback, `GRANT_FORGED_OR_TAMPERED`. Action: engage the kill switch, stop allocating under that `authorization_id`, preserve the ledger and quarantine directory as-is, and require the owner to revoke the authorization (`TRAINING_AUTHORIZATION_REVOCATIONS.json` is the existing mechanism) before anything restarts.

## 4. What would have to be true before any of this runs against a GPU

1. The owner provisions a key and signs an authorization (separate, owner-approved action; not done, not proposed here).
2. Two independent builds of the training image produce the same digest (register SUP-1 / C39; **not done**, the environment manifest carries `container.image_digest: null, status: NOT_BUILT`).
3. The hash lock `requirements/train.txt` is installed with `--require-hashes` into that image (**not done**).
4. The detectors marked DESIGN above exist and have their own tests.
5. Independent review of `orca/train/dryrun/` (**not done**).
