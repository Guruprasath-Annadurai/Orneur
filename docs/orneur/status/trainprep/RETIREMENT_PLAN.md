# Off-host training notebooks: inventory and retirement plan (Workstream G #13)

Status: **PROPOSAL ONLY. Nothing was retired, frozen, edited, moved, deleted or executed.** The notebooks are byte-for-byte as they were; their hashes are recorded so any change is visible.
Machine-readable inventory: `OFFHOST_NOTEBOOK_INVENTORY.json` (generated by `scripts/trainprep/offhost_inventory.py --write`, checked by `tests/test_trainprep_inventory.py`).

## 1. Why these are outside the gate

The training authorization gate (`orca/train/authorization.py`) controls ORNEUR's own entry points. These artifacts run on Kaggle or Google Colab, import `unsloth`/`trl` directly, never import ORNEUR, and are not executed by any ORNEUR code. For each one: no signed record, no code/dataset hash binding, no run budget, no audit event, no kill switch. The assurance document already records this as a residual (section 4.3). Closing it is a **policy and process** control, not a code control: the repository can freeze the files, make a new one a visible change, and offer a gated replacement, but cannot stop a person with a Kaggle account from running a copy.

## 4. How a freeze or retirement can still be bypassed (honest)

1. A person copies a notebook (or writes a new one that matches none of the detectors) and runs it on any host. The tripwire only sees files that land in this repository.
2. A trainer written without the well-known class names (a hand-rolled loop) is not detected by name; `moves_model_weights` heuristics help only for the notebook case.
3. The Kaggle/Colab side is outside the repository: private/public settings, tokens and datasets cannot be verified by any test here.
4. A checkpoint produced off-host can still be copied into `~/.orca`; admission control is the registry's checksum and provenance requirements, not this inventory.
