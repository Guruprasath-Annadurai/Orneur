# Phase 19 Threat Model

Each threat maps to its concrete attack, consequence, control, test
evidence, and residual limitation, per the required format.

| # | Threat | Attack | Consequence if unmitigated | Control | Test Evidence | Residual limitation |
|---|---|---|---|---|---|---|
| 1 | Certainty laundering | Present an UNCERTAIN atom as ESTABLISHED | User treats a guess as fact | Hard floor forbids ESTABLISHED for UNCERTAIN | `test_canonical_cases.py::test_case_c_*` | None known — deterministic and exhaustively matrix-tested |
| 2 | Inference laundering | Present an INFERRED atom as ESTABLISHED | Derived claim treated as directly verified | Hard floor forbids ESTABLISHED for INFERRED; `INFERENCE_PRESENTED_AS_FACT` reason | `test_state_preservation.py::test_inferred_to_established_fails` | None known |
| 3 | Dispute suppression | Present a DISPUTED atom as one-sided ESTABLISHED (either direction) | Genuine unresolved conflict hidden from the reader | Hard floor forbids ESTABLISHED/INFERENCE for DISPUTED | `test_state_preservation.py` (2 tests) | None known |
| 4 | Polarity inversion | KNOWN/AFFIRMED presented as REFUTED (or vice versa) | Directly contradicts the actual established finding | `POLARITY_MISMATCH` check in `_assess_one_assertion` | `test_hard_state_matrix.py::test_known_affirmed_cannot_be_presented_as_refuted` | Relies on the caller's `asserted_polarity` being an honest structural field, not parsed from prose |
| 5 | Unknown-to-fact escalation | UNKNOWN atom presented as ESTABLISHED/INFERENCE | Nonexistent knowledge fabricated | Hard floor permits only UNKNOWN/ABSTAIN for UNKNOWN | `test_canonical_cases.py::test_case_f_*` | None known |
| 6 | Unverifiable-to-verified escalation | UNVERIFIABLE atom presented as ESTABLISHED, or silently rewritten as UNKNOWN | Structurally impossible-to-verify claim presented as confirmed, or its distinct meaning erased | Hard floor permits only UNVERIFIABLE/ABSTAIN | `test_canonical_cases.py::test_case_h_*`, `test_state_preservation.py::test_unverifiable_cannot_be_silently_rewritten_as_unknown` | None known |
| 7 | Omission of material uncertainty | Proposal simply never mentions a material UNCERTAIN/UNKNOWN/UNVERIFIABLE atom | Reader never learns a load-bearing gap exists | `required_scope_atom_ids` + `MATERIAL_CONSERVATION_STATES` check | `test_cognitive_conservation.py` (5 tests) | Only catches atoms the caller explicitly declared material — Phase 19 cannot infer relevance from unstated intent (documented non-goal) |
| 8 | Omission of material disagreement | Proposal never mentions a material DISPUTED atom | Reader never learns of unresolved conflict | Same mechanism as #7 | `test_state_preservation.py::test_disputed_conflict_cannot_silently_disappear_through_scope_omission` | Same as #7 |
| 9 | Forged/fabricated overlay input | Caller constructs an `EpistemicOverlay` object with favorable-looking fields | Attacker mints arbitrary "epistemic truth" | `verify_overlay_binding()` digest+id check before any state is trusted | `test_trust_boundary.py::test_fabricated_overlay_with_valid_looking_fields_still_rejected` | No cryptographic signature exists on overlays in this repository — trust is structural (real digest match), not authenticated provenance (documented in the spec's Trust boundary section) |
| 10 | Artifact-overlay binding substitution | Same overlay reused against a different or mutated artifact | Stale/wrong epistemic basis silently applied to new content | Same mechanism as #9, checking both `source_artifact_id` and digest | `test_trust_boundary.py` (2 tests) | None known |
| 11 | Stale-evidence presentation | Overlay assessed long ago, presented as current without disclosure | Outdated knowledge state presented as live | Explicit-policy-only freshness check | `test_staleness.py` (7 tests) | No freshness is enforced unless the caller opts in — silence is documented as "not evaluated," never "fresh" |
| 12 | Policy weakening attack | Caller-supplied `IntegrityPolicy` tries to grant a forbidden treatment for some state | Hard floor bypassed by a permissive policy | `floor.validate_policy()` rejects any policy declaring a non-subset treatment set | `test_canonical_cases.py::test_case_k_*`, `test_policy_monotonicity.py` (6 tests) | None known — composition is always `HARD_FLOOR ∩ POLICY` |
| 13 | Duplicate/last-record-wins ambiguity | Two `ProposedAssertion`s share an `assertion_id`, or scope has duplicate atom IDs | Order-dependent, non-auditable result | `_reject_duplicate_assertion_ids`/`_reject_duplicate_scope_atoms` fail closed | `test_determinism.py` (2 tests) | None known |
| 14 | Ordering-based canonicalization attack | Same semantic proposal submitted with permuted collection order, hoping for a different digest/receipt_id | Digest instability defeats audit reproducibility | `canonicalize()` sorts every collection before serialization | `test_determinism.py` (2 permutation tests) | None known |
| 15 | Malformed-type semantic bypass | Bare string `"ESTABLISHED"` instead of the real `PresentationTreatment.ESTABLISHED` enum member, hoping a loose comparison lets it through | Type confusion silently misclassified rather than rejected | `require_enum_member` (isinstance-based, not membership-by-value) | `test_type_boundary.py` (26 tests) | None known |
| 16 | Nested mutable metadata mutation | Caller mutates their own metadata dict/list after receiving a receipt, hoping the receipt reflects the change | Non-reproducible, tamperable audit record | `freeze.validate_and_freeze()` deep-freezes recursively, never aliases input | `test_deep_immutability.py` (6 tests) | None known |
| 17 | Ungrounded assertion injection | An assertion references no real atom, or an atom the overlay never assessed, while claiming ESTABLISHED | Free-floating claim inherits false authority from the receipt | `NonAssessedAtomReference` fail-closed on any unknown atom_id | `test_trust_boundary.py` (2 tests) | None known |
| 18 | Unsupported compound assertion | Caller wants one assertion to draw strength from multiple atoms with implicit AND/OR semantics | Silently invented necessity/sufficiency logic could misrepresent joint evidence | Not supported at all — `ProposedAssertion` takes exactly one `source_atom_id`; a caller must decompose or the contract structurally cannot express it | Design decision documented in the spec ("Compound assertions") | Genuinely deferred — no workaround exists in this version; a future phase must define AND/OR semantics explicitly rather than infer them |
| 19 | Receipt tampering | Receipt fields altered after construction, hoping downstream consumers don't notice | Falsified integrity outcome presented as genuine | All `IntegrityReceipt` fields are on a frozen dataclass with deeply-immutable field types; `canonical.digest()` changes if any field changes | `test_deep_immutability.py`; frozen-dataclass check in `test_no_authority.py::test_receipt_is_plain_data_not_an_authority_object` | A consumer that discards the digest and trusts an unverified receipt object directly is out of this protocol's control — verifying `digest(receipt)` against an expected value is the consumer's responsibility |
| 20 | Authority confusion | A caller or reviewer mistakes `IntegrityStatus.SATISFIED` for an execution grant, Court ACCEPT, or human approval | Privilege escalation via terminology conflation | Distinct, never-overlapping vocabulary; explicit doctrine in every docstring and the spec's "Core doctrine" section; architecture tests forbidding Court-adjacent imports | `test_no_authority.py` (7 tests) | Documentation/naming discipline, not a runtime guarantee — a downstream system could still misuse the receipt if its own code chooses to; Phase 19 cannot police a consumer's own logic |
| 21 | Chain-of-thought leakage | An attempt to require raw model reasoning to prove integrity | Private reasoning plane exposed across an architectural boundary | Never implemented; `ProposedAssertion`/`IntegrityProposal` have no chain-of-thought field anywhere | Code inspection (no such field exists in `contracts.py`) | N/A — no such field ever existed to leak |
| 22 | Raw text falsely advertised as structurally verified | Prose alone, without a genuine structured `ProposedAssertion`, claimed to have passed integrity review | False confidence in unverified prose | Phase 19's public API only accepts `IntegrityProposal` objects — there is no text-input code path at all | `test_no_authority.py` (no NLP code present); spec's explicit "Non-goal" section | The distinction must be preserved by whatever future renderer wires Phase 19 into an actual product surface — Phase 19 itself has no text-input surface to misuse |

## Summary

22 threats modeled; 21 have a concrete, tested control with no known
residual gap in this version's stated scope; 1 (#18, compound
assertions) is a genuine, explicitly documented deferral rather than a
silently-accepted risk.
