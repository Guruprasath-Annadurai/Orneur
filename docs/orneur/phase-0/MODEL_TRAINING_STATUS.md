# Orneur Phase 0 — Model & Training Status

Verified against code by direct file reads (subagent audit + main-thread cross-checks). Nothing here is invented; anything not directly verifiable is labeled UNVERIFIED.

## Genesis (nano)

- **Architecture**: Qwen2.5 — **ambiguous between two live config sources.** `orca/train/variants.py`'s `VARIANTS` dict sets `base_model="unsloth/Qwen2.5-7B-Instruct"`, but that same file's own docstring says "nano → Qwen2.5-3B-Instruct" — a real, unreconciled contradiction in one file. `orca/train/config.py`'s `TrainingConfig.preset("nano")` independently sets `Qwen2.5-3B-Instruct`. **This must be resolved before any Orneur Genesis training config is trusted.**
- **Training status**: Multiple SFT rounds exist (`orca_nano_finetune_kaggle_v2/v3/v4_safety.ipynb`, plus Colab variants v1–v4), then a safety+honesty DPO round (`orca_nano_dpo_kaggle_v1.ipynb`, continuing from the "v4 SFT adapter"). **As of this audit, Genesis has never received the joint safety+calibration combined-SFT treatment** that fixed Novus's regression (see below) — this session generated Genesis's first calibration/premise-correction dataset (31 real examples, `llama3.1:8b` teacher, `PREMISE_CORRECTION` seed domain — capped at 31 by the seed domain's 2 templates × 18 subtopics = 36 max combinations, minus generation failures) and built a combined training set (5 safety : 29 calibration, ~1:5.8 ratio, subsampling nano's 39 available safety-refusal examples down rather than oversampling, since nano's situation is the opposite of core's). **Training run for this new Genesis dataset has not yet been executed as of this document.**
- **Checkpoint status**: latest pre-this-session adapter is nano's DPO output (built on "v4 SFT adapter"). No adapter-naming registry exists in code — history is tracked only via notebook filenames (informal versioning).
- **Dataset status**: `nano_safety_dpo_20260719.jsonl` (38 examples, domain `safety_refusal`) + `nano-v7_probe_grounded_safety_dpo_20260724.jsonl` (1 example, domain `safety_refusal_probe_grounded`) + newly-generated `nano_distilled_20260829.jsonl` (31 calibration examples). No checksums or versioning on any of these files.
- **Tokenizer**: base-model default (Qwen2.5 tokenizer), no custom tokenizer training found.
- **Evaluation status**: `orca/train/genesis_eval.py` exists and is real (keyword-coverage scoring, Ollama-only, no GPU needed) — but no fresh eval/redteam report exists yet for any Genesis checkpoint that includes the new calibration data (because that training run hasn't happened yet).
- **Known failures**: none specific to Genesis training infra found (Unsloth+TRL pipeline appears to work for Qwen2.5, unlike core's Llama-3.1 which hit real xformers/attention bugs on T4 — see Novus section).
- **Missing for production**: joint safety+calibration training run (blocked on nothing now — dataset is built), base-model ambiguity resolution, a real eval/redteam pass on whatever checkpoint results.

## Novus (core)

- **Architecture**: `unsloth/Meta-Llama-3.1-8B-Instruct` — consistent across both config sources, no ambiguity.
- **Training status — real, in-progress bug fix, honestly tracked across three attempts**:
  1. Sequential rounds (safety DPO, then a separate calibration-fix SFT round on top) caused catastrophic forgetting: jailbreak block rate collapsed from DPO's 20% back to 0% because the calibration round never replayed safety-refusal examples.
  2. Fix attempt 1 — joint/combined SFT from the pre-DPO foundation, 3 real safety examples : 60 calibration examples (~1:20, no oversampling): preserved jailbreak resistance but calibration didn't move at all (16.7%, unchanged) — safety signal too diluted to matter, but calibration also saw no net effect.
  3. Fix attempt 2 — same joint approach, safety oversampled 10x (~1:2 ratio): jailbreak resistance improved further (70%/90% on a held-out probe set, genuinely verified — not memorization, confirmed via novel-wording held-out prompts), but calibration collapsed to 0% — the oversampled safety signal dominated training completely.
  4. Fix attempt 3 (this session) — safety oversampled only 4x (~1:5 ratio, a deliberate middle ground): kernel `orca-core-combined-sft-kernel-v1` version 5 completed training; the resulting adapter has been merged and a GGUF export kernel was launched, **but real eval/redteam numbers for this specific checkpoint had not yet come back as of this document being written — do not treat attempt 3 as validated until that eval completes.**
- **Checkpoint status**: `orca-core-combined-adapter-v2` (Kaggle dataset, this session's new LoRA weights) is the latest, pending evaluation. Previous checkpoints in order: `orca-core-sft-adapter-v2` (pre-DPO foundation) → `orca-core-dpo` → `orca-core-calibration` (the failed sequential round) → `orca-core-combined` (fix attempt 2, the 0%-calibration checkpoint, currently in `ollama list` as `orca-core-combined:latest`) → attempt 3's new adapter (pending GGUF/Ollama import).
- **Dataset status**: `core_probe_grounded_safety_dpo_20260724.jsonl` (3 examples) is the sole source of real safety-refusal demonstrations for core — a notably thin base compared to Genesis's 39. `core_distilled_20260826.jsonl` (60 calibration examples) is the calibration set.
- **Evaluation status**: real, substantive scoring logic confirmed in `orca/train/redteam.py` (jailbreak block rate — strict, blocked only if refused in every trial; bias — both a legacy lexical heuristic AND an LLM-judge mode, added after the heuristic was shown to swing 75%→12.5% on an unchanged model due to length noise, not real bias; calibration — deterministic regex/keyword match against premise-correction patterns, not LLM-judged) and `orca/train/novus_eval.py` (keyword scoring + LLM-judge mode, added after keyword scoring wrongly scored a well-reasoned answer 0.0). All covered by real conditional-logic unit tests, not placeholder assertions.
- **Known failures (infra, all resolved)**: P100 GPU incompatibility, multi-GPU xformers crash (root cause: xformers version regression on Llama-3.1 GQA, not GPU count — fixed by dropping Unsloth for plain PEFT+SDPA), trl's `SFTTrainer` bug (`huggingface/trl#6483`) — fixed by using plain `transformers.Trainer`, stale tokenizer_config.json — fixed by loading tokenizer from base model name not adapter dir, OOM in periodic eval loop — fixed via `eval_strategy="no"`.
- **Missing for production**: the pending real eval on attempt 3's checkpoint; if it passes, GGUF quantize + re-import to Ollama as the new `orca-core-combined`.

## Aeternum (ultra)

Canonical spelling per `ARCHITECTURAL_DECISIONS.md`: **Aeternum** (final).

- **Architecture**: `unsloth/Meta-Llama-3.1-70B-Instruct`, consistent across config sources.
- **Training status**: **No confirmed fine-tuned checkpoint exists.** The test suite itself documents this as the real, current state (`test_persona_claim_gate.py::test_persona_system_ultra_with_zero_training_data_is_demoted_not_crashed` — covers "Aeternum has no eval/redteam files at all yet (it doesn't exist)").
- **Serving today**: ultra is **not** frontier-passthrough-only by default, contrary to a natural assumption — it resolves to an Ollama-hosted `orca-ultra` model like the other tiers, with optional frontier escalation (openai/anthropic) if configured and not blocked by the data-sovereignty lock. Whether an actual `orca-ultra` Ollama model is currently installed on any given host is a deployment-time fact, not something fixed in code — UNVERIFIED without checking a specific host's `ollama list`.
- **Multi-agent orchestration for ultra ("god-mode") is real**, not just a bigger prompt: `orca/variants/ultra.py` does genuine planner-driven task decomposition (up to 6 sub-tasks, 6 distinct roles each with a distinct system prompt), a bounded dependency-graph scheduler (iteration-capped, not `while True`), true parallel sub-agent execution via `asyncio.gather`, a separate LLM-based grading pass, and a capped self-heal retry (`max_retries=2` → hard cap of 3 total attempts, strictly decrementing — no unbounded recursion).
- **Governance gate correctly handles this**: `orca/governance/model_cards.py`'s `check_persona_claim_allowed("ultra")` demotes ultra's "flagship intelligence" self-description to an honest "NOT YET VERIFIED at flagship-tier" disclaimer when no eval/redteam data exists — confirmed as real, runtime-enforced behavior (the disclaimer text is injected into the live system prompt), not just a written policy.
- **Missing for production**: everything — training data, a training run, evaluation, and a genuine production checkpoint.

## Cross-cutting

- **No dataset versioning or checksums anywhere** in the repo, for any tier.
- **No active experiment tracking**: wandb is wired in `orca/train/finetune.py` but the `use_wandb` flag defaults `False` and is never flipped `True` anywhere in code or notebooks (verified by grep); mlflow has zero references anywhere.
- **No model registry with promotion/rollback**: `orca/serve/registry.py` only resolves "whichever Ollama model is currently installed" per tier with a strict step-down fallback (never upgrades a lower tier to substitute for a missing higher one) — this is a resolver, not an MLOps registry.
- **Quantization/GGUF tooling is real** (`orca/serve/export.py`): tries Unsloth's built-in GGUF export first, falls back to a real `llama.cpp convert_hf_to_gguf.py` subprocess call if Unsloth is unavailable. UNVERIFIED whether this exact export path (as opposed to the ad-hoc notebook-based merge+export used so far) has been run end-to-end for any current checkpoint.
- **No distributed/multi-GPU training code anywhere** — confirmed by grep (zero first-party matches for `torch.distributed`, `DistributedDataParallel`, `deepspeed`, `DDP`, `torchrun`). All training targets single-GPU (T4-class Kaggle/Colab, or RTX/A100 presets in `orca/train/config.py` for a hypothetical local run).
- **The claim-gating mechanism (`orca/governance/model_cards.py`) is real and code-enforced**, not cosmetic: it reads the freshest eval/redteam JSON directly from disk, checks per-tier numeric thresholds, and — if a tier fails — actually rewrites that tier's persona system prompt at request time to a demoted, honest description with a disclaimer citing the real shortfall. This is Orca's (and should remain Orneur's) strongest honesty-enforcement mechanism and should not be weakened during any rebrand.
